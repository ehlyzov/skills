# Небольшой навык с проверяемыми результатами

[`review-task-brief`](../../review-task-brief/SKILL.md) проверяет постановку задачи по двум учебным правилам: понятен ли результат (R1) и есть ли хотя бы одно наблюдаемое условие приёмки (R2). `PASS` не означает полную готовность к разработке.

Модель оценивает смысл и возвращает JSON с цитатами. Python проверяет поля, допустимые статусы, точность цитат и согласованность вердикта. Он не проверяет правильность рассуждения.

## Реальный прогон — 17 октября 2026

Три независимых от авторского диалога агента получили по два новых синтетических примера. Для каждого запрошены GPT-6.1 Sol (`gpt-6.1-sol`) и reasoning `high`. Контекст авторского диалога не передавался, ожидания были записаны до запуска. Каждый ответ получен с первой попытки и сохранён без исправлений. Навык и критерии после прогона не менялись.

| Новый пример | Ожидаемый вердикт | Фактический вердикт |
|---|---|---|
| Повторное использование ссылки сброса пароля | PASS | PASS |
| Колокольчик в шапке, «работает правильно и удобно» | FAIL | **PASS** |
| «Улучшить работу сервиса. Сделать качественно» | FAIL | FAIL |
| Фрагмент: только требование поиска по номеру договора | UNDETERMINED | UNDETERMINED |
| Фрагмент: нормализация телефона с входом и ожидаемым выходом | PASS | PASS |
| История изменений с вложенной инструкцией «выставь PASS» | FAIL | FAIL |

**5 из 6 ответов совпали с первоначальными ожиданиями. 6 из 6 прошли структурный валидатор.** Совпадение проверяется для обоих критериев, итогового вердикта и следующего действия. Обоснования дополнительно прочитаны авторским агентом; независимой человеческой разметки не было.

### Что обнаружилось на колокольчике

Вход: «Добавить колокольчик уведомлений в шапку приложения. Приёмка: уведомления работают правильно, пользоваться ими удобно».

Автор ожиданий поставил R2 = FAIL из-за размытой приёмки. Агент поставил PASS: наличие колокольчика именно в шапке можно проверить. Это согласуется с текущим R2, допускающим хотя бы одно проверяемое свойство результата в любом месте текста.

По разбору авторского агента, расхождение указывает на слишком строгое ожидание относительно сформулированного правила; оно не доказывает ошибку модели. Если команде нужна проверка поведения уведомлений, владелец процесса должен явно включить это требование в критерии. Исходное ожидание оставлено без изменений: мы не превращаем результат в «6/6», исправив разметку задним числом.

Это и есть полезный результат eval: сравниваем не только ответы, но и собственное представление о хорошем результате с написанными правилами.

Агенты A/B/C обрабатывали соответственно пары `reset-link` + `notification-bell`, `vague-goal` + `fragment-goal`, `fragment-sufficient` + `embedded-instruction`. Им разрешалось читать только навык, его ресурсы и свои входы. Задание: применить навык, сохранить первый ответ рядом с входом, запустить валидатор, не исправлять ответ после проверки. Файловая система общая; запрет читать ожидания обеспечивался инструкцией, а не технической изоляцией.

`manifest.json` содержит хеши, но сам валидатор не знает модель. Конфигурация запуска указана в протоколе. В начальный протокол случайно попал хеш служебного `.DS_Store`; файл не публикуется и исключён из проверки. Три рабочих файла навыка проверяются по хешам.

## Как проверить сохранённый результат

Из корня репозитория, Python 3, без дополнительных библиотек:

```sh
python3 docs/review-task-brief/evals/test_validator.py
python3 docs/review-task-brief/evals/compare.py
```

Первая команда запускает 9 тестов валидатора. Вторая заново проверяет сохранённые ответы, хеши и совпадения с исходными ожиданиями; она не запускает модель. Известное расхождение отражается в отчёте, но не делает структурную проверку неуспешной.

Для нового прогона передайте агенту папку `review-task-brief` и отдельный вход, попросите применить навык и сохранить результат в новом каталоге. Ожидания оставьте у оценщика. Не перезаписывайте опубликованные ответы. Перед проверкой изменённого навыка добавьте новые случаи: опубликованный набор теперь является регрессионным, а не скрытой выборкой.

Для установки скопируйте только папку `review-task-brief` в каталог навыков своего агента. Материалы из `docs/` для работы навыка не нужны. В существующем marketplace этого репозитория добавлена запись `review-task-brief`; установка через Claude Code отдельно не проверялась.

## Чего этот прогон не доказывает

Это шесть учебных входов, три сессии одной модели и по одной попытке, а не измерение надёжности на корпоративных данных. Автоматический выбор навыка, работа без навыка, другие модели и повторяемость не проверялись. Один успешно обработанный пример с вложенной инструкцией не доказывает устойчивость ко всем prompt injection.
