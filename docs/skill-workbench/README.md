# Skill Workbench

[Навык](../../skill-workbench/SKILL.md) помогает создать или улучшить другой навык: выяснить существенные требования, записать проверяемые ожидания, собрать реализацию и проверить её на примерах. При наличии штатного skill-creator использует его для оформления, но не зависит от него.

Владелец процесса определяет достаточность результата и последствия ошибок. Агент сам решает рутинные вопросы реализации. Уже полученные ответы не нужно повторять в новой анкете.

## Использование

Скопируйте папку `skill-workbench` в каталог навыков своего агента. Документация и результаты из `docs/` для установки не нужны. В Codex после загрузки навыка:

```text
Используй $skill-workbench. Создай навык для [задача].
Вот наши правила, примеры входов и признаки хорошего результата: [...].
```

Для существующего навыка:

```text
Используй $skill-workbench. Улучши навык в [путь].
Вот вход, фактический ответ и что в нём не так: [...].
debug=true. Сохрани артефакты в новом каталоге [путь].
```

`debug=true` — договорённость в тексте запроса, а не встроенный переключатель Codex. Она включает сохранение входа, версии навыка, выходов, проверок и кратких оснований решений. В отчёте видны применённые требования, доказательства, допущения и ограничения. Это не запись скрытых рассуждений модели. Создаваемый навык тоже должен поддерживать документированный режим отладки.

Примеры и ожидания составляются до запуска. Исполнителю не передают ответы оценщика. Для исправления сохраняются исходная версия и первое ошибочное выполнение; повторный прогон получает отдельный каталог. Несовпадение с ожиданием требует разбора: ошибка может быть и в ожидании.

## Что проверяет код

Python 3.9+ и стандартная библиотека:

```sh
python3 tests/skill_workbench/test_check_debug.py
python3 skill-workbench/scripts/check_debug.py <run-directory>/debug.json
```

Валидатор проверяет структуру отчёта, допустимые статусы, ссылки на существующие файлы внутри каталога запуска и запрет общего PASS при непройденных обязательных проверках. Семантическую правильность решений он не определяет. Код 0 означает корректный отчёт, а не успешность исследуемого навыка.

Для проверок используется словарь `PASS`, `FAIL`, `BLOCKED`, `NOT_RUN`. Формат конечного результата создаваемого навыка определяется его задачей: JSON не обязателен для любой работы с текстом.

## Что проверено 17 октября 2026

Требования к самому workbench [подтверждены пользователем](brief.md). Два первых запроса исполнили отдельные агенты с чистым контекстом, затем ещё один агент проверил исправление. Во всех трёх запусках запрошены `gpt-6.1-sol` и reasoning `high`. Ожидания составлял авторский агент до запуска; исполнителям они не передавались. Файловая система общая, разделение обеспечивалось инструкцией, а не sandbox.

1. **Неопределённый запрос об исследовании конкурентов.** Агент задал три существенных вопроса, обозначил предлагаемые варианты, сохранил черновик и debug-отчёт. Готовность не заявил; тесты будущего навыка честно отметил NOT_RUN.
2. **Создание извлекателя поручений по заданным правилам.** Агент создал навык, получил 8/8 совпадений на синтетических примерах в своём авторском контексте, проверил обычный и отладочный режим на одном входе. JSON результата совпал; debug содержит основания включения и исключения поручений. Однако при чтении обнаружилась ошибка самого workbench: автор разрешил себе выбрать правило преобразования дня недели в дату, назвав это рутинной реализацией. Поэтому этот прогон не объявлен полностью успешным, несмотря на зелёные проверки созданного навыка.
3. **Исправление и новый запрос о сроках.** В workbench добавлено различие между технической реализацией и правилами интерпретации данных. На новом примере со «следующей пятницей» агент показал два возможных толкования, привёл дату, на которой они расходятся, и запросил выбор. Поведение не было финализировано без ответа.

Исходные версии, ожидания, ответы и ошибочный выбор сохранены в [артефактах](evaluation-2026-10-17/); итоговый разбор — [assessment.json](evaluation-2026-10-17/assessment.json). Успешный debug-отчёт целевого извлекателя можно посмотреть [здесь](evaluation-2026-10-17/concrete-request/target-debug/meeting-001/debug.json). `meeting-actions` внутри материалов — результат эксперимента с сохранённым дефектом, не дополнительный готовый продукт для установки.

Проверка самого Python-валидатора: 7 тестов пройдены. Внутри экспериментального создания навыка дополнительно прошли 4 отрицательные проверки его валидатора. Все три сценария сохранили debug-отчёты. Стандартная проверка упаковки целевого навыка сначала получила BLOCKED из-за отсутствия PyYAML в окружении исполнителя; исходная ошибка сохранена. В основном окружении с уже доступной зависимостью она затем прошла. Упаковка актуального workbench также проверена.

Это проверка конкретных сценариев и одной узкой правки, а не измерение надёжности. Восемь примеров извлекателя выполнял его автор; независимого исполнителя этого созданного навыка не было. Полный набор первой версии после изменения не повторяли, проверили адресную регрессию. Автовыбор, сравнение с работой без навыка, повторяемость и другие модели не проверялись. Запись marketplace добавлена, установка через Claude Code отдельно не проверялась.
