# Отладка meeting-actions

`debug=true` передаётся текстом вызова вне входного JSON. Используй указанную `debug_dir` как новую папку запуска вне навыка; если она уже содержит артефакты, выбери новый суффикс. Если путь не задан, создай новую папку рядом с рабочими результатами. Не отправляй артефакты внешним сервисам.

Сохрани минимум: `input.json`, `output.json`, снимок `skill/SKILL.md` и этого reference, `runtime.json` с известными моделью и контекстом без догадок, `checks.json` с фактическими проверками, `debug.json`. Не сохраняй постороннюю историю или скрытый ход мыслей. Вход с чувствительными данными можно минимально отредактировать, явно отметив редакции и влияние на воспроизводимость. Цитаты проверяй по фактически использованному исходному вводу.

`debug.json` содержит ровно поля:

```json
{
  "status": "PASS",
  "summary": "Проверки этого запуска выполнены.",
  "artifacts": ["input.json", "output.json", "skill/SKILL.md", "skill/references/debug.md", "runtime.json", "checks.json"],
  "decisions": [{"decision":"Оставить owner=null", "basis":"Исполнитель не назван в безличном поручении.", "evidence":["input.json", "output.json"], "assumptions":[]}],
  "checks": [{"name":"Структура и точные цитаты", "status":"PASS", "detail":"Фактическая проверка завершилась без ошибок; семантика проверяется отдельно.", "evidence":["checks.json"]}],
  "limitations": []
}
```

Статусы отчёта и проверок: PASS, FAIL, BLOCKED, NOT_RUN. Это оценка объявленного набора проверок, не доказательство общей надёжности. Обязательная FAIL/BLOCKED/NOT_RUN запрещает итоговый PASS. Все пути в artifacts уникальны, относительны папке запуска и существуют; ссылки evidence ссылаются на artifacts. Фиксируй фактические проверки и объясняй ограничения. Если инструмент не запускался, не заявляй успешный запуск. Не включай сам debug.json в artifacts.

Для каждого включения/исключения опиши краткое наблюдаемое основание: явное обязательство/необходимость, явный владелец, исходный или вычисленный срок, точная цитата. Для пустого ввода сослаться на input.json и отсутствие расшифровки достаточно. Это краткое обоснование решения, не протокол внутреннего рассуждения. Debug не меняет выходной JSON и не даёт разрешение на сообщения или создание задач.
